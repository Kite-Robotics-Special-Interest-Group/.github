# 如何写「复现文档」

> **一句话**：让一个**没参与过这项工作、也几乎零基础**的成员，照着文档一步步做，
> 最后得到**和你一样的结果**（同样的文件、同样的数字、同样的现象）。
>
> 本文讲写法规矩；[模板](reproduction-template.md)可以直接复制。真实的例子见
> [Kite M0 复现文档](https://github.com/Kite-Robotics-Special-Interest-Group/Kite/blob/main/docs/reproduce-m0.md)。

---

## 1. 为什么值得写

| 场景 | 没有复现文档 | 有复现文档 |
| --- | --- | --- |
| 新人加入 | 只能看你在群里口述，反复问 | 照着做，1 小时上手 |
| 评审 | 只看结论，无法核对 | 按步骤验证，能指出哪一步不对 |
| 出问题 | "我这边是好的" | 逐步比对，定位到具体版本/参数 |
| 交接 | 人走了就断了 | 文档就是交接 |

**判断标准**：文档里的每条命令，别人复制粘贴就能执行；每步都有「预期看到什么」。

---

## 2. 必备结构（8 节，缺一不可）

### 0. 标题 + 一句话

「复现：X（在 Y 平台上 / 用 Z 版本）」。第一段写清**最终能得到什么**（一张图、一个数字、一个能转的电机）。

### 1. 版本与前置条件

**软件**：仓库 commit 或 tag（`git rev-parse --short HEAD`）、操作系统与版本、工具版本（`python -V`、`cmake --version`、`gcc --version`、固件版本号）。
**硬件**：板卡型号与编号、结构版本、电控板版本、传感器型号、电源规格。
**账号/授权**：需要谁邀请、需要什么下载权限。

> 没有版本号的复现文档等于没写。**至少写一个 commit/tag**。

### 2. 输入与产物

| 类别 | 要写什么 |
| --- | --- |
| 输入文件 | 名字、来源（网盘/HF/厂商）、大小、**sha256** |
| 中间产物 | 每个步骤生成什么，放在哪个目录 |
| 最终产物 | 文件名、大小、sha256、如何验证 |

### 3. 步骤（每步三段式）

```markdown
### 步骤 3：导出 ONNX

操作：
```bash
python scripts/export_onnx_fp16.py --model ... --out ...
```

预期：输出最后三行形如
```
[OK] encoder.onnx 1090.3 MB
```
目录里出现 `encoder.onnx` 与 `denoiser.onnx`。

失败怎么办：报 `ModuleNotFoundError: onnx` → 在容器内执行（见 §1）。
```

**必须**：命令可直接复制；预期输出要具体（文件、日志关键行、数字范围）；失败排查写最常见 2–3 条。

### 4. 验收标准（可测量）

不要写"能跑"，要写：

- 文件：`xvla_encoder.hmm` 大小 638.9 MB（±2%）
- 接口：输入名/形状/dtype 与文档表格一致
- 性能：236 ms/动作，允许 **±20%** 偏差（写清测量方法：预热次数、重复次数）
- 现象：夹具闭合、串口打印 `READY`、示波器波形频率 20 kHz ±2%

### 5. 耗时与资源

磁盘（需要多少空闲）、内存、网络（下载量）、人员（几个人、是否需要焊台/示波器/万用表）。

### 6. 已知偏差与限制

- 允许的差异（fp16 舍入、线程数差异、不同批次元件）
- 未完成/未验证的部分（明确写"未验证"，别让人误以为验证过）

### 7. 变更记录

| 日期 | 改动 | 维护人 |
| --- | --- | --- |
| 2026-10-16 | 初版 | @某人 |

## 3. 三类方向的写法提示

### 软件 / 固件

- 给出**一条能复制执行的命令**，不要只写"运行脚本"
- 依赖写版本（`requirements.txt`、`package.json`、SDK 版本）
- 预期日志贴**关键行**，不要贴几百行
- 数据/模型大文件写清来源与 sha256

### 电控

- 板号 + 固件版本 + 烧录方式（工具、波特率、接线）
- **上电顺序**与安全注意事项（谁先接、限流多少）
- 预期现象：电源灯、串口输出、蜂鸣器/继电器动作、示波器测量点与波形
- 测量记录：用万用表/示波器的读数范围

### 机械

- 图纸版本与文件（`mech/arm-v1.2.pdf`）
- 材料与加工方式（3D 打印/CNC/钣金）、后处理
- 装配顺序与关键尺寸/公差（写清配合：H7/g6 等）
- 验收：称重、尺寸测量点、干涉检查结果（附照片）

## 4. 常见错误写法

| ❌ 错误 | ✅ 正确 |
| --- | --- |
| "按之前的流程做" | 把流程写出来（或给出链接 + 版本） |
| "安装了依赖" | `pip install -r requirements.txt`（版本锁定在文件里） |
| "跑一下脚本" | `python scripts/xxx.py --a 1 --b 2` + 预期输出 |
| "结果是 236 ms" | 236 ms（预热 2 次、重复 5 次取均值；±20% 内可接受） |
| 只写成功路径 | 写 2–3 个最常见失败及处理 |
| 图片/日志只发在群里 | 存进仓库 `docs/assets/`（小图）或网盘（大图），文档里给链接 |

---

## 5. 和 Issue / PR 的关系

- **Issue**：新任务里写「复现方式」字段（至少写环境与验收）
- **PR**：改了流程/参数，就同步更新复现文档；PR 描述里附「我按文档从零跑过一遍」
- **定期回归**：里程碑前后，按复现文档跑一遍，把差异记到「已知偏差」
